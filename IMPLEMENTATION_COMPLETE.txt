WHAT WAS FIXED
================================================================================

ROOT PROBLEM:
  Report shows "0 Anomalies" despite real power issues in the system

ROOT CAUSE:
  Two independent systems not sharing data:
  - PowerSupplyParser: Extracts power data ✓
  - AnomalyDetector: Never received that data ✗

THE FIX:
  Connected the two systems so AnomalyDetector can use parsed power data

CODE CHANGES MADE
================================================================================

FILE 1: src/DeepDive/Pipeline/RenderStep.php
  Location: Lines 270-278
  Change: Pass power_data + additional context to AnomalyDetector
  Impact: Detector now receives complete power supply information
  
  Added metadata:
    - 'power_data' → Parsed power supply data (voltage, current, health)
    - 'source_registry' → What data sources were available
    - 'facts' → Bundle metadata

  Impact: Ensures data reaches analyzePowerSupply() method

    - 'power_data' → From metadata
    - 'source_registry' → From metadata
    - 'facts' → From metadata
    - 'tenant_id' → From metadata
    - 'nas_id' → From metadata

FILE 3: src/DeepDive/AI/AnomalyDetector.php
  Location: Lines 147-245 (added ~100 lines)
  Change: Analyze power_data for anomalies
  Impact: Now detects 9 different power anomaly types
  
  Detection logic:
    ✓ Health assessment (critical/warning/caution status)
    ✓ Redundancy status (degraded PSU)
    ✓ PSU failures (not present, unplugged, failed)
    ✓ Voltage anomalies (out of spec, approaching limits)
    ✓ Current anomalies (over-current conditions)
